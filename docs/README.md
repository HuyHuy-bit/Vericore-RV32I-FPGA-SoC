# Documentation

Start with the [project README](../README.md) for the evidence and project overview.
Then follow the question you want answered:

| Question | Document |
|---|---|
| How does the CPU work? | [Architecture](architecture.md) |
| Why were these choices made? | [Design decisions](decisions.md) |
| What changed performance or FPGA area? | [Measured studies](studies.md) |
| How is correctness checked? | [Verification](verification.md) |
| What runs in the FPGA implementation? | [FPGA evidence](fpga.md) |
| How do I build and use the SoC? | [SoC guide](soc.md) |
| Where are the actual tool screenshots? | [EDA visuals](portfolio/README.md) |
| Which records support each claim? | [Evidence ledger](evidence.md) |

[Coverage detail](coverage.md) and the [result-file format](../results/FORMAT.md)
are reference material. Superseded design proposals and task lists are in the
[archive](archive/README.md); they are not instructions for the current project.

Architecture owns behavior, decisions owns rationale, and the evidence ledger
owns the full measured tables. The README keeps only the strongest results and
links to those sources.
